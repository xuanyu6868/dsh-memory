# 给 DeepSeek Harness 的后续操作单

本轮 Codex 修改的是 PR #1 分支 `ops/openviking-deployment` 中的维护工具、模板和文档；没有访问用户 Mac、改已安装上游包、重启 App 或读写真实记忆。

## 可直接发送的提示词

> 请接手 https://github.com/xuanyu6868/dsh-memory/pull/1 的最新提交，并按本文件完成剩余本机验收。
>
> 先拉取实际 PR 分支，记录 commit，阅读 AGENTS.md、docs/design.md、ops/scripts/README.md 和本文件。运行 npm run check、npm test。不要重新安装已可用模型或覆盖云端凭据。
>
> 核对本机配置与模板差异后，只合并实际需要的字段。保存未发送草稿与当前工作状态，执行一次必要的 App 重启，确认实际 desktop profile 加载了 actor、显式 recallLimit 和单次 context 超时配置。GitHub 提交不代表本机已生效。
>
> 用更新后的脚本完成下面 A–D，逐项区分“本仓库模拟测试”和“本机实际通过”。任何失败都保留事实、说明原因，不把等待超过8秒自动算作通过。不得上传真实记忆、聊天、密钥或原始日志；只更新脱敏结论和必要的版本/时间。

## A. 用户与项目内容备份 / 恢复演练

1. 先对真实用户做只读内容导出（包含用户和全部项目根），放到仓库外的新目录。检查 manifest.complete、roots、文件数量和每个 SHA256，并单独确认已迁移到 `peers/deepseek-harness/memories/events` 的工作日志被包含。不要以旧脚本“成功若干文件”的结果代替。
2. 明确此导出不包含配置、索引、ACL/tags、会话或记忆根外的 identity/soul。需要备份这些内容时沿用现有本机备份方案，不能称内容导出为完整灾备。
3. 另创建少量有唯一测试前缀的合成个人/项目内容，用 `--root` 分别导出到第二个临时目录。运行 restore 默认预览验证不发请求；再用 `--target-root .../memories/ops-restore-<唯一标记> --apply` 在一次性子树恢复。只演练合成数据，不把整份真实记忆复制到个人空间污染检索。
4. 核对文本、URI映射、文件数、读回结果，并检查实际向量更新/检索是否完成。测试成功后只清理本次明确创建的测试 URI，不删分类父目录、真实数据或真实备份。源测试数据与恢复数据都需要清理。

## B. 实际隔离

- 使用更新后的 verify-peer-scope.py，指定本次合成事实的准确 project-uri/personal-uri，重跑5项。旧版本脚本可能因统计缺失而误判，旧5/5不转记为新版通过。
- App重启后，在项目A、B的新聊天窗口各问一次，检查实际注入结果；仅运行API脚本不能证明GUI配置已生效。
- 单独核对MCP代理的项目身份。上游0.5.26代理是profile进程级，不能自动保证跟随每个会话工作区。当前广搜能力属于明确保留的跨项目工具，不得声称完整工具隔离。
- 检查目前用户级空间里是否仍有项目事实。迁移只处理明确归属，保留备份；`actor`本身不会隐藏已有用户级项目内容。

## C. 挂起测试：测整轮，不只测单次HTTP

**先确认没有需要立即完成的语音/工具任务。由本机Harness操作服务，在恢复步骤准备好后执行。**

1. 健康状态先记录一次“已初始化会话”的提问→模型开始回答时间，并准备一个全新会话。保留配置与正常endpoint，确认知道如何恢复launchd。
2. 在本机临时卸载服务：`launchctl bootout gui/$(id -u)/ai.openviking.server`。确认进程退出、1933释放。
3. 运行 `python3 -B ops/scripts/blackhole-server.py --port 1933 --hold 90 --duration 180`。工具只收连接不回HTTP，最多180秒退出；它本身不会恢复launchd。
4. 分别测试已初始化会话和新会话；普通文字与语音至少各一次。记录从用户提交到模型开始执行/回答的完整时间、请求次数、最终结果和App是否可点击。新会话初始化、context、旧端点、原始检索、legacy peer兼容查询都可能消耗时间。
5. 记录：8000ms只是一次context请求超时。若总等待超过目标，**标“整轮8秒目标未达成”**；不要继续靠缩短一个HTTP超时假装有总预算。给出有依据的配置取舍，或把需要修改上游的总deadline/取消传播作为独立补丁方案。
6. **无论测试成功、超时或报错，均在finally中停止黑洞工具并恢复服务**：`launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/ai.openviking.server.plist`。确认1933由真实OpenViking监听，`ov status`和`openviking-server doctor`正常，待处理队列恢复，普通聊天/语音可继续。未恢复不算完成。

不在运行测试时关闭唯一可操作窗口；自动退出的黑洞工具也不等于已恢复服务。
